SECTION 09Language and content

The interface speaks about text patterns with the caution of a lab note and the brevity of a label. It never borrows the vocabulary of verification, and it never says in one language more than it says in the other.

9.1 Voice

Plain

Short sentences. Concrete nouns. No metaphors of detection, hunting, or exposure. If a sentence needs a second sentence to walk back its claim, rewrite the first.

Procedural

Describe what the model did: read text, weighted signals, produced an estimate. The product is a method, not an oracle.

Bounded

Every claim carries its limit in the same breath: text only, review level, estimate. The limit is not a footnote; it is part of the sentence.

SayDo not say
“The text repeats the same phrasing.”“This reviewer is a bot.”
“The estimate is based on text patterns.”“We verified this review.”
“Not enough text to estimate.”“No data.” / “Insufficient confidence.”
“A signal toward manipulation influenced the estimate.”“This is a fake review.”
“Indicative — limited text.”“Low confidence.” / “67% sure.”
“No estimate.”“0 / 100.”
“3 reviews found.”“Page score: 42.”
“This language is not supported yet.”“French is fully supported.”

Person, not pattern. A band may describe a review's text; it may never describe the person who wrote it. The pronoun for a reviewer is “they”, never “he” or “she”, and the interface does not guess identity from a name.

The substitution test

Replace “organic” with “reads like a spontaneous review” and replace “manipulated” with “shows patterns associated with manipulation”. If the sentence still claims a fact about a person or a product, delete it.

9.3 Bilingual behaviour

The interface is English and French. The model is not necessarily both: French model support is conditional on its own evaluation gate (D23). Translating the interface does not translate the model, and the panel must never imply that it does.

The language control changes interface copy only. Review text is sent with an optional language hint; if the language is unsupported, the result is UNKNOWN with UNSUPPORTED_LANGUAGE, shown in the interface language. Live review text is never machine-translated.

The active interface language is stored locally with the other preferences. The panel sets lang on its root when the interface is French, so screen readers switch pronunciation. French strings are never set in all caps.

Never infer coverage

Do not write “English and French reviews” in the unsupported-language string. Do not show a French flag or an “FR supported” badge. The only honest statement is the one the copy deck already makes: “This language is not supported yet.”

9.6 Layout of copy

  • Wrap, never truncate. A band name, reason, or button label is never cut with an ellipsis. If it does not fit, the container grows or the sentence is rewritten.
  • No hyphenation in band names, buttons, reason sentences, or signal summaries. Body copy may hyphenate inside a correctly tagged French block.
  • Two sentences maximum for an empty or error block. One is better. The action is a separate element.
  • Buttons are one or two words. “Retry”, not “Try the analysis again”.
  • Design at French length. The disclaimer and the LOW qualifier are the longest persistent strings; both are tested at 320 px.
  • No slang, no exclamation, no emoji, no “Oops”. The product is calm even when it fails.

SECTION 10Accessibility

Accessibility is a constraint on the honesty of the design: if the band position is only visible as a colour, or the evidence only as a hover, the interface is not saying the same thing to everyone.

10.1 Standard and scope

The extension panel, the on-page chips, the toolbar badge label, and the options page target WCAG 2.2 AA. The PDF you are reading is a design document, not the product; its own accessibility is limited by print export and is not the conformance target.

Perceivable

Contrast, non-colour cues, text alternatives, 200% zoom and reflow at 320 px.

Operable

Keyboard path for every action, visible focus, 44 px targets, no timing traps, reduced motion.

Understandable

One meaning per state, plain language, consistent placement, errors that say what happened.

10.5 Screen reader

Announcements

  • Row. “Review 2, score 34, Likely manipulated, band 2 of 6, adequate evidence, reads like promotional copy. Collapsed, button.”
  • Low evidence. “Score 64, Mixed signals, band 4 of 6, indicative, limited text.”
  • Unknown. “No estimate. Not enough text to estimate.”
  • Signals only. “Descriptive signals only — no score.”
  • Chip. “Review 2, score 34, Likely manipulated, band 2 of 6. Open in TrustLoop.”
  • Rescan. “Results updated. 3 reviews found.” Politeness is set on the page bar; focus does not move.

What is hidden

The six-stop track, the marker, the axis tick, the chevron, and the tick ladder are decorative once the text carries the value. They are aria-hidden or CSS-only. The score, band, evidence, and direction are always in the accessible name.

What is not

The contribution percentage is announced as “31 percent contribution”, never as “31 percent confident”. The evidence popover is a labelled dialog with a close button and a heading.

SECTION 11Motion

Motion explains a change of state. It never performs confidence, never fills a measure, and never makes a number arrive like a result.

11.1 Three durations

Opacity uses linear timing. Expansion uses cubic-bezier(.2,0,0,1). No spring, no bounce, no overshoot.

11.3 Reduced motion

Under prefers-reduced-motion: reduce, every duration collapses to 0 ms: expansion is instant, the crossfade is a swap, and the skeleton pulse stops. Nothing is lost: the content was never carried by the motion. The same rule applies to forced-colors mode, where the browser replaces the palette and the interface must remain legible through system colours.

No performance

The score does not animate because the model is not “thinking” at the user. The estimate arrives; the interface shows it.

No suspense

No delayed reveal, no staged signals, no “analysing…” sequence of fake steps. A loading line and a skeleton are enough.

No attention loop

Nothing pulses after load. The only repeating motion is the skeleton pulse while a request is genuinely pending.

11.4 Implementation notes

  • Animate opacity and transform only, except the row height needed for expansion. No animated box-shadow, filter, or background-position.
  • Respect the reduced-motion query in both CSS and script; do not rely on the media query alone if a script drives the expansion.
  • Keep the list scroll position when a row expands, and never animate the scroll itself.
  • Pause the skeleton pulse when the panel is not visible; a hidden tab should not animate.

The test

Motion never carries the result. If the score only reads correctly while it moves, the design is using animation to make the claim — and that is the one thing it may not do.
