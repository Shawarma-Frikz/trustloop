SECTION 04Typography

An editorial serif for judgment, an engineering sans for the interface, and a mono for anything that behaves like a measurement. Three families, tightly scoped.

4.1 The three families

NEWSREADER · DISPLAY AND VERDICT
A second reading.

Newsreader carries the chapter titles, the verdict band, and the document covers. It has a literary, slightly calligraphic voice without becoming decorative. It is never used for controls, metadata, or dense body copy. Available under the SIL Open Font License; self-host the WOFF2 files with the extension.

IBM PLEX SANS · INTERFACE
Review 3 · Likely organic · Adequate evidence
The text shows a concrete usage detail and varied wording. Signals describe what moved the estimate, not whether the review is true.

IBM Plex Sans is the working voice: rows, buttons, labels, helper text, and the panel. It is plain enough to disappear and distinctive enough not to read as a default system stack. Do not replace it with Inter, Roboto, Poppins, or Montserrat.

IBM PLEX MONO · MEASUREMENT AND PROVENANCE
73 · 24% · tl-text-1.1.0 · 0–100

IBM Plex Mono is reserved for scores, percentages, review indices, model versions, reason codes, and the small scale numbers. It makes the number feel measured without turning the whole interface into a terminal.

Fallbacks

Georgia → Segoe UI → Cascadia Mono. Fallbacks exist for resilience, not for design. Never ship a screenshot where the fallback is doing the work.

Loading

Self-host WOFF2 in the extension. No external font request from the panel: it would leak the page session and break offline use.

Licensing

All three are OFL. Keep the licence files beside the fonts and list them in NOTICE.

4.4 Numbers

Score

73

Integer, 0–100, tabular, never a decimal. No percent sign. The score is always adjacent to a band name in the panel.

Contribution

24%

Only when the explainer is stable and validated. Always labelled “contribution”; never “confidence”, “probability”, or “accuracy”.

French runs longer. Design at the French string, then check English does not look sparse. The claim must be identical in both languages; only the sentence length changes.

  • Sentence case. French accents stay; never set a French sentence in all caps.
  • No truncation of meaning. Wrap to a second line; never end a band name or reason with “…” .
  • No hyphenation in band names, buttons, or reason labels. Body copy may hyphenate with lang="fr".

  • Same strength. “Probablement” is not weaker or stronger than “Likely”; both describe the band, not the reviewer.

SECTION 05Space and layout

A 4 px base, a narrow panel, and a strict left edge. The layout should feel typeset: one column, clear rules, and enough air that a serious estimate does not look like a notification.

Anatomy

  1. Header. Wordmark, language control. 44 px.
  2. Page bar. Host name, count, rescan. Counts only; no page score.
  3. Review list. The only scrolling region.
  4. Review row. Index, score or state, band, evidence, top signal.
  5. Expanded measure. Score, band, six stops, marker, qualifier.
  6. Signals. Up to five, with direction and optional contribution.
  7. Footer. Disclaimer and model version. Persistent.

Panel width 360 px; minimum 320; maximum 420. The header and footer do not scroll. The list keeps its scroll position when a row expands.

5.4 Placement on the host page

The chip sits at the top-right of each review card, 8 px inside the card's padding box. It must not cover the reviewer's actions, the rating, or the review text. If the host layout has no safe corner, place the chip after the review body, aligned left, on its own line.

The chip's visual height is 26 px; its interactive target is 44 × 44 px, extending invisibly around it. It never overlaps another chip. On narrow viewports, chips stack with the review, not over it.

Isolation

The panel and chips live in a Shadow DOM. Host page CSS does not enter; extension CSS does not leak. Use all: initial on the host, then the token layer. No !important wars with the page.
